# מחשבון העלות האמיתית של הרכב — "ההגה בידיים שלי"

מחשבון עלות החזקת רכב לאורך זמן: עלות חודשית/שנתית/כוללת, פירוט הוצאות,
בחירת דגם ממאגר משרד התחבורה עם מילוי אוטומטי, השוואה בין עד שלושה רכבים,
כניסה עם קוד אימות (OTP), וחיבור ליצירת לידים.

בנוי ב-**Vite + TypeScript**, ללא תלויות ריצה (vanilla). כל החישובים מכוסים
בבדיקות אוטומטיות (Vitest). RTL מלא, נגישות, ומותאם למובייל.

> המחשבון הוא כלי עזר לקבלת החלטה ואינו ייעוץ פיננסי או המלצה לרכישה.

---

## הפעלה ופיתוח

דורש **Node.js 18+**.

```bash
npm install       # התקנת תלויות פיתוח
npm run dev       # שרת פיתוח (http://localhost:5173)
npm test          # הרצת כל הבדיקות (Vitest)
npm run build     # בנייה לפרודקשן → תיקיית dist/
npm run preview   # תצוגה מקדימה של הבנייה
```

> הערה: אם ההתקנה חוסמת סקריפטים (npm חדש), אשרו את esbuild:
> `npm approve-scripts esbuild && npm rebuild esbuild`.

## מבנה הקוד

הפרדה מלאה בין שכבות. שמות משתנים באנגלית; כל הטקסטים והמספרים החשובים מרוכזים.

```
src/
  config.ts              # מקור אמת יחיד: הנחות, ברירות מחדל, צבעי מותג,
                          #   CTA_URL, MAKE_LEAD_WEBHOOK_URL, ספים
  strings.ts              # כל טקסטי הממשק בעברית (מקום יחיד לעריכת ניסוחים)
  types.ts                 # מודלי הנתונים
  format/format.ts         # פורמט ₪/אחוזים, פסיקים חיים תוך כדי הקלדה,
                            #   ולידציית טלפון/מייל
  validation/validate.ts   # שגיאות (שליליים) ואזהרות רכות (ערכים לא סבירים)
  calc/                    # הנוסחאות - מתועדות, מבודדות, נבדקות:
    energy.ts              #   דלק / חשמל / פלאג-אין
    financing.ts           #   הלוואה (שפיצר), ריבית בתקופת ההחזקה, יתרה
    insurance.ts           #   הערכת ביטוח לפי שאלון (גיל/ותק/תביעות/כיסוי)
    licenseFee.ts          #   הערכת אגרת רישוי לפי מחיר הרכב (טבלת משרד התחבורה)
    totals.ts               #   אגרגציה: עלות כוללת + פירוט קטגוריות
  compare/compare.ts        # לוגיקת השוואה, מסקנה מאוזנת, איתור פערי-קטגוריה
  data/                     # models.ts+json (מאגר דגמים), cities.ts+json (ערים לחישוב ק"מ)
  integrations/leads.ts     # שליחת ליד ל-Webhook של Make (לרב מסר)
  analytics/track.ts        # שכבת אירועים (stub, ללא שליחת מידע כרגע)
  state/                    # store (מצב, localStorage, מיגרציית סכמה) + defaults
  ui/                       # login (OTP), steps (אשף 3 שלבים), results,
                            #   comparison, course (פופ-אפ), modal, components, styles.css
tests/                      # בדיקות Vitest (69+ בדיקות)
```

### עריכות נפוצות
- **ניסוחים/טקסטים** → `src/strings.ts`
- **הנחות וברירות מחדל** (מחירי דלק, ביטוח, ספים) → `src/config.ts`
- **צבעי מותג** → `BRAND` ב-`src/config.ts` (וב-`ui/styles.css` כמשתני CSS)
- **לוגו** → `public/logo.png`, מוצג בכותרת (`brandMark` ב-`ui/app.ts`)
- **תמונת הקורס בפופ-אפ** → `public/founder.jpg`
- **כתובת ה-CTA לקורס** → `COURSE_URL` ב-`src/config.ts`

## חיבור ליצירת לידים (רב מסר, דרך Make)

הכניסה למחשבון (שם + טלפון + מייל + אישור דיוור, עם קוד אימות) יכולה לשלוח
כל ליד חדש ל-**רב מסר**, דרך Webhook של **Make (Integromat)**. כך פרטי
ההתחברות של רב מסר נשארים בצד Make ולא נחשפים בקוד האתר.

**הגדרה חד-פעמית:**
1. ב-Make.com: New Scenario → מודול ראשון **Webhooks → Custom webhook** → Add.
   Make ייתן כתובת URL ייחודית.
2. מודול שני: מחפשים את האפליקציה **Rav Message** (רב מסר), מתחברים לחשבון
   (Connect account) לפי הוראות ההתחברות של רב מסר בתוך Make.
3. בוחרים פעולה כמו **Add/Update Contact**, וממפים את השדות שמגיעים
   מה-Webhook (`name`, `phone`, `email`, `marketingConsent`) לשדות המתאימים
   ברשימת התפוצה ברב מסר.
4. שומרים ומפעילים (Activate) את התרחיש.
5. מדביקים את כתובת ה-Webhook בתוך `MAKE_LEAD_WEBHOOK_URL` ב-`src/config.ts`,
   ואז `npm run build`.

כל עוד השדה ריק, שליחת הליד מדולגת בשקט (`src/integrations/leads.ts`) -
לא שובר את תהליך ההתחברות. השליחה היא "ירי וסיום" (fire-and-forget): גם אם
היא נכשלת (למשל אין אינטרנט רגעי), המשתמש עדיין נכנס למחשבון כרגיל.

> הערה: כרגע קוד ה-OTP (קוד האימות) הוא **דמו בצד לקוח** בלבד ומוצג על
> המסך. לשליחת SMS אמיתי עם קוד יש לחבר שירות שליחה בצד שרת (למשל גם
> את זה אפשר לעשות דרך Make + רב מסר, או ספק SMS אחר).

## מאגר דגמי רכב (כמו יד2)

בחירת דגם בשלב 1 ממלאת אוטומטית **סוג דלק**, **צריכת דלק**, ו**אגרת רישוי
משוערת** (הכל מסומן כהערכה, ניתן לשינוי).

- **מקור:** נתוני משרד התחבורה הפתוחים (`data.gov.il`, מאגר WLTP) - כ-5,000 דגמים, 131 יצרנים.
- **צריכת דלק** נגזרת מפליטת CO2 הרשמית.
- **אגרת רישוי** מחושבת ממחיר הרכב לפי טבלת משרד התחבורה הרשמית (בתוקף 01.04.2026).
- **רכב חשמלי:** אין נתוני קוט"ש רשמיים במאגר - נשארת הערכת ברירת מחדל.
- **מחיר וביטוח:** לא נגזרים מהדגם - נשארים למילוי (עם עוזר הערכת ביטוח לפי שאלון).

**רענון המאגר** (אחת לתקופה, כשיוצאים דגמים חדשים):

```bash
node scripts/build-models.mjs   # מוריד ומעבד -> src/data/models.json
npm run build
```

## אירוח (שרת סטטי בלבד - בלי צורך בשרת/מסד נתונים)

המחשבון הוא קבצים סטטיים בלבד (HTML+CSS+JS, כולל תמונות ופונטים מוטמעים).
**כל אחסון אתרים תומך בזה** - אין תלות בפלטפורמה ספציפית.

### אם יש לך אתר קיים עם מפתח/מארח משלך
1. `npm run build` → נוצרת תיקיית `dist/`. אפשר לדחוס אותה ל-ZIP להעברה נוחה.
2. שולחים את הקובץ למי שמנהל את האחסון, עם הבקשה:
   **"להעלות את התוכן כמו שהוא לתיקייה בשרת (למשל `/calculator/`),
   בלי שום שינוי - זה אתר סטטי, לא דורש שרת אפליקציה או מסד נתונים."**
3. הכתובת הסופית תהיה `https://האתר-שלך/calculator/` (או כל נתיב אחר
   שיבחרו) - עובד מכל דפדפן, בלי תלות בחשבון Claude.

### אם רוצים גם אחסון חינמי מהיר לבדיקה
- **GitHub Pages / Netlify / Vercel / Cloudflare Pages** - כולם תומכים
  בגרירת תיקיית `dist/` או חיבור לריפו. הפרויקט מוגדר עם `base: "./"`
  כדי לעבוד גם בתת-נתיב, לא רק בשורש הדומיין.

## אנליטיקה (עתידי)

`src/analytics/track.ts` חושף `track(event)` ו-`registerAnalyticsHandler`.
כרגע אינו שולח מידע לשום מקום. לחיבור עתידי (Google Analytics / Meta Pixel) -
רשמו handler שממפה את האירועים: `calculator_started`, `calculation_completed`,
`comparison_added`, `savings_scenario_opened`, `otp_requested`,
`login_completed`, `consultation_clicked`.
